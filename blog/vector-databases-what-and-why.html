Vector Databases: The Engine of Modern AI

AI Databases Vector Search

If you've been paying attention to the tech ecosystem lately, you've probably heard the term "Vector Database" thrown around everywhere. From OpenAI's latest features to the boom in Retrieval-Augmented Generation (RAG) applications, vector DBs are at the core.

But what exactly are they, and why can't we just use Postgres for this?

The Problem with Traditional Search

Relational databases (like PostgreSQL or MySQL) and document stores (like MongoDB) are phenomenal at exactly matching data. If you query for SELECT * FROM users WHERE age > 25, you get deterministic results. Even with full-text search (like Elasticsearch), you are fundamentally matching keywords.

But what happens when you want to search by meaning? What if a user searches for "a comfortable place to sit" and your database only contains the word "sofa"? A keyword search fails. This is the gap vector databases fill.

Enter Embeddings

To understand vector DBs, you must first understand embeddings. Machine learning models (like LLMs) translate data—text, images, audio—into arrays of numbers called vectors (or embeddings). These vectors represent the "meaning" of the data in high-dimensional space.

If two pieces of text have similar meanings, their vectors will be physically close to each other in this multidimensional mathematical space.

For example, the vector for "dog" and "puppy" will be very close. The vector for "car" will be far away.

Why We Need Specialized Databases

Comparing two arrays of 1,536 floating-point numbers (the size of an OpenAI embedding) is computationally cheap. Comparing one vector against one billion vectors to find the closest match (Nearest Neighbor Search) is computationally massive.

Vector databases are purpose-built to solve this exact problem at scale. They use specialized indexing algorithms like HNSW (Hierarchical Navigable Small World) or IVF (Inverted File Index) to find Approximate Nearest Neighbors (ANN) in milliseconds, rather than seconds or minutes.

When Should You Use One?

  • Semantic Search: Searching documents based on meaning rather than keywords.
  • Recommendation Systems: "Users who liked this item also liked..." (Items are represented as vectors).
  • RAG (Retrieval-Augmented Generation): Giving LLMs long-term memory by retrieving relevant context from a knowledge base before generating an answer.
  • Image/Audio Search: Searching for an image using another image, or searching audio by melody.

The Ecosystem Today

The space is evolving rapidly. We have managed, purpose-built solutions like Pinecone and Weaviate. We have open-source powerhouses like Milvus and Qdrant. And we even have vector extensions for traditional DBs, like pgvector for PostgreSQL.
